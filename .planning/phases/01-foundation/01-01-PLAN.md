<threat_model>
## Trust Boundaries (Plan 01 scope)

| Boundary | Description |
|----------|-------------|
| browser → Next.js server | All public traffic; no auth assumed at this layer in PLAN-01 |
| Next.js server → Supabase API | Carries publishable key (anon-equivalent); RLS enforces auth |
| Service-role client → Supabase | Carries master key; restricted to `lib/supabase/admin.ts` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `SUPABASE_SERVICE_ROLE_KEY` leakage to client bundle | mitigate | Variable name does NOT carry `NEXT_PUBLIC_` prefix; only imported in `src/lib/supabase/admin.ts` (server-only); `.env.local` is gitignored; Task 2 adds explicit JSDoc warning |
| T-01-02 | Spoofing | Use of insecure `getSession()` in proxy | mitigate | `src/lib/supabase/proxy.ts` uses `supabase.auth.getClaims()` exclusively (verifies JWT against JWKS); RESEARCH.md Pitfall 2 explicitly forbids `getSession()` for authorization |
| T-01-03 | Tampering | Deprecated `middleware.ts` silently shadowing `proxy.ts` | mitigate | Task 2 verification asserts no `middleware.ts` file exists; only `proxy.ts` at project root |
| T-01-04 | Information Disclosure | Wrong env var name (`ANON_KEY` vs `PUBLISHABLE_KEY`) causing config drift | mitigate | Task 1 forces canonical 2025+ name `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`; matches all client/server/proxy code paths |
| T-01-05 | Information Disclosure | `.env.local` accidentally committed | mitigate | Task 1 adds `.env.local` and `.env*.local` to `.gitignore` before any auth keys are written |
</threat_model>
